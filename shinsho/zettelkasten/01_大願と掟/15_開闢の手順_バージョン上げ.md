# 開闢の手順：バージョン上げ

## 掟

**Flutter現世の具現化前には必ず先にバージョンを上げよ。**
これは高天原における最も犯してはならない運用の禁忌である。

## 絶対の手順

```
1. pubspec.yaml の version を更新（最初に！）
       ↓
2. コード修正・具現化
       ↓
3. git commit
       ↓
4. git push
       ↓
5. GitHub Actions が自動ビルド → Play Store へ自動配信
```

### 具体例

```yaml
# pubspec.yaml
# 修正前:
version: 1.0.0+13

# 修正後（最初に行う！）:
version: 1.0.0+14
```

## なぜ最初にバージョンを上げるのか

| 理由 | 説明 |
|------|------|
| **versionCode重複防止** | Play Storeは `versionCode`（`+`の後）の重複を許さない。「Version code has already been used」でデプロイ失敗 |
| **CIの前提** | GitHub Actionsはpushをトリガーに自動ビルド。バージョンが上がっていないとCIが正常終了してもPlay Storeが受け付けない |
| **巻き戻し不能** | Play Storeは同じversionCodeでの再アップロード不可。バージョン上げ忘れは「コードは正しいのに配信できない」状態を生む |
