## 試練の根本思想

「**人間が端末画面を見て合否を判定できる**」を第一義。
各ステップに「人間の確認方法」と「自動化の判定基準」を併記。
---

## 自動化の三段階

| 段階 | 方式 | 人間の関与 |
|------|------|----------|
| 第一 | 手順書を見ながら手動実行 | 操作＋判定 |
| 第二 | スクリーンショット＋Vision API | 判定のみ |
| 第三 | ADBパイプライン完全自動化 | UI変更時の手順修正のみ |
---

## 設計原則

| 原則 | 説明 |
|------|------|
| 操作の明示 | タップ対象・入力内容を具体的に |
| 期待結果の可視化 | 画面変化を言葉で記述 |
| 自動判定基準の併記 | 機械が検証できる条件 |
| 前提条件の明記 | 開始時の状態を明確に |
---

## 環境情報

| 項目 | 値 |
|------|-----|
| 端末 | P30 (Android 10) / 1080×2340 / DPI 480 |
| ADB | `192.168.0.18:5555` |
| パッケージ | `com.shorie.lifequest` |

## 自動化パイプライン構成

## 既知の制約

| 制約 | 対策 |
|------|------|
| ADB日本語不可 | ASCII英字テストデータ |
| IME変換 | `input keyevent` 逐次入力 |
| 画面解像度変化 | Vision API動的座標検出 |
