## 実装設計

1. **Firebase**：1プロジェクト（例 `takamagahara-utsushiyo`）に現世ごとAndroidアプリ登録 → `google-services.json` を各現世へ配布
2. **SDK**：`firebase_core` + `firebase_crashlytics` + `firebase_analytics`（全Flutter現世共通）
3. **Play API**：`androidpublisher/v3` — `reviews.list`（レビュー取得）、`reviews.reply`（返信）、`reports`（vitals/クラッシュ）、`useracquisition`（インストール数）
4. **DAU/定着率**：Firebase Analytics（Analytics Data API）— Play API では取れないためSDK埋め込み必須
5. **新Cron**：久延毘古神「週次運用監視奏上」（月曜8:30）→ Discord `#自律-定時`

### レビュー監視ループ（イベント駆動・6時間毎）の詳細

- スクリプト: `~/.hermes/scripts/play_review_monitor.py`（no-agent Cron `0 */6 * * *` → Discord #自律-定時）
- 通知条件: 低評価（★≤2）OR 重要キーワード（バグ/クラッシュ/課金/データ消失/性能 の5系統・部分一致）
- 重複防止: 専用ステート `~/.hermes/play_review_state.json` に既読レビューIDを現世別記録。初回は全既存を「ベースライン化」し通知しない。
- 新着なし時は空stdout（0バイト）→ Hermes の SILENT_MARKER により Discord 配信を抑止（ノイズ防止）。
- 週次 `weekly_ops_monitor.py`（集計型・月曜8:30）とは別ループ。ステートファイルも分離（競合防止）。

### 残る外部設定（創造主様の手動操作が必要・3点）

1. **GA4連携**: Firebase Console → プロジェクト設定 → 連携 → Google Analytics を有効化
2. **Analytics Data API有効化**: GCP Console → APIライブラリ → `analyticsdata.googleapis.com` を有効化（＋SAに権限付与）
3. **Play Developer Reporting API有効化**: GCP Console → APIライブラリ → `playdeveloperreporting.googleapis.com` を有効化

※ 両サービスアカウントとも Service Usage API の権限が無く（403）、API有効化はエージェント側で不可。創造主様の手動操作が必須。

### 週次KPI 指標定義と計算式（第三者が再現できるように明文化）

実装: `~/.hermes/scripts/weekly_ops_monitor.py` 3️⃣（久延毘古神・週次運用監視奏上、月曜8:30 → Discord #自律-定時）

| 指標 | 定義 | 取得元（API） | 計算式 |
|------|------|--------------|--------|
| DAU | その日アプリを一度でも起動したユニークユーザー数 | GA4 Analytics Data API `activeUsers`（dim `date`） | 週次 = Σ(日次activeUsers) ÷ 日数 |
| 週間新規ユーザー | 対象週に初回起動したユニークユーザー数 | GA4 `newUsers`（= first_open） | 期間内の newUsers 合計 |
| DL数（近似・下限） | 新規ユーザーを DL 下限近似として使用 | GA4 `newUsers` | = 週間新規ユーザー（未起動者は計上されず下限） |
| DL数（厳密・ストア計上） | Play 上のインストール数 | Play Console バルクレポート（Cloud Storage `gs://pubsite_prod_rev_*`） | 要手動で GCS 設定＋SA に storage 権限 |
| D1/D7/D30定着率 | 初回起動日を D0 とし、Dn 日後にも再起動した割合 | GA4 `runReport` + `cohortSpec`（cohort=firstSessionDate, cohortNthDay, `cohortActiveUsers`/`cohortTotalUsers`） | Dn = cohortActiveUsers[nth=n] ÷ cohortTotalUsers[nth=0] ×100（単一コホート） |
| 前週比（WoW） | 今週値の前週からの変化率 | 上記各値の前週/今週2期間取得 | (今週 − 前週) ÷ 前週 ×100% |

**アラート閾値（前週比で異常な落ち込み、`--wow-alert-*` で変更可）**:
- DAU 前週比 ≤ −30% → 🔴
- 新規ユーザー 前週比 ≤ −50% → 🔴
- D1定着率 前週比 ≤ −10pt → 🔴

**DL数のデータ源に関する重要知見**:
- Play Developer Reporting API は vitals 専用（crash/ANR/wakelock/slow-render 等）で、獲得（インストール）系の計量は存在しない。
- 旧 androidpublisher v3 の `reports`・`stats`（DL数）・`useracquisition` は API から削除済み。
- よって DL数は GA4 `newUsers`（近似）か Play Console バルクレポート（厳密）の2択。

### 重要知見（神書に刻む）

- androidpublisher v3 の `reports`（DL数）・`vitals`・`useracquisition` エンドポイントは **既にAPIから削除済み**。DL数は Firebase Analytics（first_open）か Play Console バルクレポート（Cloud Storage）で代替する。
- Firebase Crashlytics に読み取り用の公開REST APIは**存在しない**（firebasecrashlytics.googleapis.com は discovery 無し）。クラッシュ検知は Play Developer Reporting API の vitals crashRate で代替。
- Firebase サービスアカウントは firebase.readonly のみ。serviceusage / IAM 権限なし。
